# Yon License Guardian

在自己的 Linux 服务器上运行的 YonSuite 采购许可占用监控与清理服务。服务通过专用 Chrome 会话读取许可看板；达到满额后，执行一次清理并复查结果。部署完成后由 systemd 常驻运行，不依赖 Codex、开发人员的电脑或本地浏览器持续在线。

这是独立开发的非官方工具，与用友及 YonSuite 不存在官方隶属或认证关系。使用前请确认你有目标企业的管理权限，并获准执行该许可的清理操作。

## 当前范围

当前版本固定针对 C3 环境 `https://c3.yonyoucloud.com` 中的以下许可，不能只改名称就用于其他环境或许可：

| 项目 | 当前值 |
| --- | --- |
| 看板路径 | 应用许可看板 → 使用中 → 供应链云 → 采购供应 → 采购管理 |
| 许可编码 | `BIP0002YB` |
| 许可类型 | `SHAREUSER` |
| 控制点 | `BIPSCM0201` |
| 领域 | `MM` |
| 容量 | 10 人 |
| 检查间隔 | 60 秒 |
| 自动清理条件 | 确认目标企业、许可、完整占用列表与计数一致，且占用达到 10 人 |
| 清理范围 | 本次确认的目标许可全部占用人员，不是只清理闲置人员 |

**满额时会清理目标许可的全部占用，可能影响正在使用该采购许可的人员。** 它清理的是许可占用，不是删除员工账号、采购订单或其他业务记录。不要将它配置为未经评估的全企业许可管理器。

## 已实现的行为

- 绑定经过人工确认的企业哈希，核对企业、目标许可、统计结果与完整分页列表。
- 未满额时持续观察；满额时通过多次读取确认状态，再提交一次清理请求。
- 提交前持久化 `pending` 日志；出现请求结果不明、复查失败或已有未完成日志时暂停，不自动重复发送。
- 清理后复查占用计数和旧占用人员是否全部消失；未达到验证条件时保留日志并暂停。
- 保存的密码由 systemd credential 提供，仅用于普通密码登录恢复。
- 遇到图像验证码、短信验证或其他登录验证时，暂停并等待人工完成验证。完成后需要人工重启监控服务。
- 通过受限 Unix socket 提供状态页面和临时可视化登录；状态页可选部署到带登录保护的公网 HTTPS 地址，可视化登录仍仅通过 SSH 隧道访问。
- 公网运行看板显示占用与监控状态，服务器独立采集全部观察到的检测记录，保留最近 24 小时，并区分自动清理、异常和历史手动测试。

当前实现是规则驱动服务。**LLM 登录恢复 Agent、验证码自动处理、外部告警和人工验证后自动恢复均未实现。** 可以在现有服务上继续扩展，但不是本版本已经提供的能力。

## 快速开始

下面只安装项目依赖并运行模拟测试，不会连接用友账号或执行真实清理。需要 Node.js 22 或更高版本和 Git。

```bash
git clone https://github.com/aroa15792-web/yon-license-guardian.git
cd yon-license-guardian
npm --prefix deploy/cloud-browser ci
npm --prefix deploy/visual-login ci
npm test
```

真实运行还需要 Linux、systemd，以及 `/usr/bin/google-chrome` 路径的 Google Chrome 和目标企业的合法账号与管理权限。不要直接把开发目录的测试命令当作服务器部署流程。

## 项目结构

```text
src/                  监控、规则、持久化日志与清理控制
deploy/cloud-browser/ 持久化浏览器、登录、企业确认与许可接口适配
deploy/visual-login/  临时可视化登录桥接
deploy/status-viewer/ 只读状态页面
deploy/public-viewer/ 公网查看页的独立回环网关与 Nginx 模板
deploy/*.sh           服务器启动与诊断脚本
deploy/*.service      systemd 常驻服务配置
test/                 模拟测试
docs/                 部署、运维与代码说明
```

CI 仅安装锁定依赖并运行模拟测试，不配置真实凭据、不启动生产服务。通过模拟测试并不等于在你的企业完成真实清理验收；上线前仍需按部署说明核验自己的环境与授权。

## 凭据与运行数据

不要把登录密码、Cookie、浏览器 profile、企业哈希、SSH 私钥、HAR、状态目录或真实业务日志提交到仓库。生产凭据应保存在服务器受保护文件中，浏览器状态与清理日志保存在专用受限目录中。

已产生的 `pending` 清理日志是避免重复操作的关键依据。不要通过删除日志、清空状态目录或循环重启来绕过暂停；先人工核对远端结果。
